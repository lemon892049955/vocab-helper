# 英语单词学习插件 · 技术方案

## 1. 方案总览
采用 **Chrome Extension Manifest V3 + TypeScript + Vite + React** 构建。翻译能力通过 **DeepSeek Chat Completions API** 提供，统一走 background service worker 发起请求，结果在本地缓存。数据默认存储在 `chrome.storage.local`，支持导出备份。

## 2. 架构图（逻辑）
```
┌────────────────── 浏览器页面 ──────────────────┐
│  content script（划词捕获 + 悬浮卡 UI）         │
│        │  chrome.runtime.sendMessage            │
└────────┼───────────────────────────────────────┘
         ▼
┌─ background service worker ─────────────────────┐
│  message router                                │
│  ├─ translate/  → provider → cache → DeepSeek  │
│  ├─ notes/      → storage 读写                 │
│  └─ export/     → 生成 CSV/JSON 下载           │
└──────┬─────────────────────────┬───────────────┘
       │ chrome.storage.local    │ HTTPS
       ▼                         ▼
   本地生词本               api.deepseek.com
```

- Popup / Options 页通过消息与 background 通信，不直接持有 Key。
- Content script 用 Shadow DOM 渲染悬浮卡，避免页面 CSS 污染。

## 4. 核心技术选型
| 关注点 | 选择 | 理由 |
|---|---|---|
| 插件规范 | Manifest V3 | Chrome 当前要求 |
| 语言 | TypeScript | 类型安全，跨模块共享类型 |
| 构建 | Vite + CRXJS | HMR 快、配置简单，支持 MV3 |
| UI | React | Popup、Options、悬浮卡统一组件 |
| 样式 | Tailwind（可选） | Popup 开发效率高；content script 用独立 CSS |
| 存储 | `chrome.storage.local` | 个人数据量足够，后续可换 IndexedDB |
| 翻译 | DeepSeek `chat/completions` | OpenAI 兼容，成本低、质量稳定 |
| 测试 | Vitest + Playwright | 单测逻辑，浏览器级验证可用 Playwright |

## 5. Manifest 设计
```json
{
  "manifest_version": 3,
  "name": "英语单词学习插件",
  "version": "0.1.0",
  "permissions": ["storage", "activeTab"],
  "host_permissions": ["https://api.deepseek.com/*"],
  "background": { "service_worker": "background.js" },
  "action": {
    "default_popup": "popup.html",
    "default_icon": "icons/icon128.png"
  },
  "content_scripts": [{
    "matches": ["<all_urls>"],
    "js": ["content.js"],
    "run_at": "document_idle"
  }]
}
```

说明：
- `host_permissions` 仅允许访问 DeepSeek，减小权限范围。
- 若后续支持多 provider，再增加对应域名或使用 `optional_host_permissions`。

## 6. DeepSeek 接入
### 6.1 配置
- Base URL：`https://api.deepseek.com`
- 模型：`deepseek-chat`（对话 / 翻译使用，优先推荐）
- `deepseek-reasoner` 适合复杂推理，翻译场景不推荐（慢且贵）。
- 接口与 OpenAI Chat Completions 兼容：`POST /chat/completions`。

### 6.2 Provider 抽象
```ts
// src/background/provider/types.ts
export interface ProviderConfig {
  provider: "deepseek";
  apiKey: string;
  baseUrl: string;
  model: string;
  targetLanguage: string;
}

export interface TranslateRequest {
  text: string;
  type: NoteType; // word | phrase | sentence
  targetLanguage: string;
}

export interface TranslateResult {
  original: string;
  translation: string;
  phonetic?: string;
  partOfSpeech?: string;
  exampleOriginal?: string;
  exampleTranslation?: string;
  keyWords?: { word: string; meaning: string }[];
  model: string;
  cached: boolean;
}
```

### 6.3 请求方式
```
POST https://api.deepseek.com/chat/completions
Authorization: Bearer <apiKey>
Content-Type: application/json
{
  "model": "deepseek-chat",
  "temperature": 0.2,
  "response_format": { "type": "json_object" },
  "messages": [
    { "role": "system", "content": "你是英汉词典与翻译助手...输出 JSON..." },
    { "role": "user", "content": "翻译文本..." }
  ]
}
```

### 6.4 Prompt 策略
- **单词**：输出音标、词性、中文释义、英文例句及例句译文。
- **句子**：先整句翻译，再拆分重点词汇和短语。
- 使用 `response_format=json_object` 提高解析稳定性。
- 对返回 JSON 做 schema 校验，解析失败时提供「重新翻译」和「文本降级输出」。

## 7. 翻译缓存
### 7.1 缓存键
```
cacheKey = sha256(normalize(text) + "|" + model + "|" + targetLanguage)
```

### 7.2 策略
- 命中缓存直接返回，标记 `cached: true`。
- 缓存写入 `chrome.storage.local`，按 LRU 或容量上限清理。
- 设置中提供「清除翻译缓存」。
- 缓存不影响已收藏笔记；收藏是持久数据，缓存是可再生数据。

## 8. 消息协议
所有 UI 与 background 的通信使用 `chrome.runtime.sendMessage`：

```
// request
{ type: "translate", payload: { text, type, targetLanguage } }
{ type: "saveNote", payload: noteInput }
{ type: "listNotes", payload: { query?, filter? } }
{ type: "updateNote", payload: { id, patch } }
{ type: "deleteNote", payload: { id } }
{ type: "exportNotes", payload: { format: "csv" | "json" } }
{ type: "getConfig" }          // 不返回 apiKey 明文，只返回是否已配置
{ type: "saveConfig", payload: { apiKey?, model?, baseUrl?, targetLanguage? } }
{ type: "testConnection" }
```

响应统一结构：
```ts
{ ok: true, data } | { ok: false, error: { code, message } }
```

## 9. 数据存储
- 收藏笔记：`chrome.storage.local`，key 为 `notes`。
- 配置：key 为 `settings`。API Key 单独 key `secret.apiKey`，避免导出或日志误带。
- 缓存：key 前缀 `cache:`，与笔记分区，可整体清除。
- 后续若单条笔记增加图片 / 大文本，可迁移 IndexedDB；接口层先抽象 `NoteStore`，便于替换。

## 10. 关键实现要点
### 10.1 划词捕获
- 监听 `document.addEventListener("mouseup", handler, true)`。
- 延时或判断目标：避免点击 Popup / 悬浮卡自身时误触。
- 对 `iframe`、`input/textarea`、`contenteditable` 先做基础支持，复杂场景标注为已知限制。
- 使用 `getBoundingClientRect()` 定位悬浮卡，并做视口边界翻转。

### 10.2 页面隔离
- 悬浮卡插入页面的根节点套 `shadowRoot`。
- 所有样式局部 scoped；不向 `window` 注入与站点冲突的全局变量。

### 10.3 错误处理
- HTTP 401：提示 Key 无效，引导到设置。
- HTTP 429：提示请求过快，后台做简单退避。
- 网络失败：保留原文本，提供重试。
- 模型返回非 JSON：降级为纯文本翻译结果。

## 11. 测试方案
- **单元测试（Vitest）**：文本归一化、类型判定、缓存 key、导出格式、JSON 解析。
- **逻辑测试**：provider mock 后验证消息路由。
- **浏览器验证（Playwright）**：加载 unpacked 插件，覆盖划词、翻译、收藏、导出流程。
- **手工清单**：英文技术文档、新闻、无 CSS 页面、登录页 / 动态页等场景。

## 12. 风险与对策
| 风险 | 对策 |
|---|---|
| API Key 泄露 | Key 仅存 local，不写日志；代码仓库忽略 `.env`，非调试页不回显 |
| DeepSeek 返回不稳定 | `response_format=json_object` + schema 校验 + 降级 |
| 页面 CSS / JS 冲突 | Shadow DOM、scoped CSS、只读事件监听 |
| 成本累积 | 缓存 + 文本长度截断 + 仅主动触发 |
| CSP 限制站点 | Content script 的变化通常不依赖页面 CSP；翻译网络请求放 background |
| 数据量增长 | storage 分片写入，导出兜底，后续迁移 IndexedDB |

## 13. 实施顺序
1. 初始化 Vite + CRXJS + MV3 + React，产出最小可加载插件。
2. 打通消息协议、存储类型、DeepSeek provider 与缓存。
3. 实现 Content Script 划词 + 悬浮卡，完成「翻译 → 收藏」闭环。
4. 实现 Popup 生词本与设置页。
5. 实现导出、补充单测和 Playwright 关键链路验证。
